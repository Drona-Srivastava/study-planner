Study Planner

Detailed technical and user documentation
Omarchy plugin for GATE and placement preparation, timetable reminders, and a local Kanban task board.

1. Purpose and design

Study Planner combines two related workflows in one Omarchy shell panel. The Agenda is driven by a weekly timetable and provides current, next, and daily schedule information. The Kanban board is for manually created tasks that move through Backlog, In Progress, and Completed.

The plugin is intentionally local-first. The UI is written in QML for Quickshell, while a Python standard-library backend stores tasks and timetable completion state in SQLite. No account, network API, or external database is required at runtime.

Theme compatibility: visual colors and fonts are read from Omarchy's Color and Style objects. The plugin does not hardcode Geist, JetBrains Mono, or a theme-specific palette.

2. Repository and installation

Repository: https://github.com/Drona-Srivastava/study-planner

omarchy plugin add https://github.com/Drona-Srivastava/study-planner.git --enable

Update an existing installation:

omarchy plugin update study-planner --yes
omarchy restart shell

Omarchy normally installs the source at ~/.config/omarchy/plugins/study-planner. The persistent database is separate at ~/.local/state/omarchy/study-planner/planner.db, so source updates do not delete tasks.

3. File-by-file component guide

3.1 manifest.json

The manifest identifies the plugin as study-planner, describes it as a productivity plugin, and registers three entry points:

Entry pointFileRole
barWidgetBarWidget.qmlIcon placed in the Omarchy bar.
panelPlannerPanel.qmlFull-screen overlay panel containing Agenda and Kanban.
servicePlannerService.qmlBackground reminder polling.

3.2 BarWidget.qml

This component creates the compact bar entry. It periodically executes planner.py agenda, uses the current or next block to build its tooltip, and toggles the panel through omarchy-shell shell toggle study-planner. The widget uses the Omarchy WidgetButton component and the bar's own font/color system.

3.3 PlannerPanel.qml

This is the primary user interface.

  • Root state: stores whether the panel is open, the selected tab, agenda JSON, task JSON, errors, date-picker state, and a timer tick used to refresh relative due text.
  • Process objects: run planner.py agenda, planner.py tasks, and mutation commands. JSON output is parsed into QML properties.
  • Header: shows the title, current date, and close control.
  • Agenda: shows the active block, the next block, and today's schedule. Timetable completion can be checked, with the existing limited undo behavior.
  • Kanban: shows three fixed columns. Drag/drop is intentionally not used. Cards have checklist, Start, Complete, Reopen, delete, and relative due-time controls.
  • Date picker: opens after a trailing @, starts on today's date, and supports arrow keys, month navigation, and Enter.
  • Time picker: opens after a trailing @@, starts from the current time, uses 24-hour hour/minute controls, and supports keyboard interaction.
  • Interaction feedback: buttons, checkboxes, picker controls, tabs, close, delete, and Add areas use a pointing-hand cursor.

3.4 PlannerService.qml

The service runs planner.py reminders every 30 seconds. The Python backend decides whether a notification is due and deduplicates notifications in SQLite. The QML service does not duplicate the reminder logic.

3.5 planner.py

The backend uses only Python's standard library: sqlite3, argparse, datetime, zipfile, XML parsing, subprocess, and filesystem utilities.

Function/areaResponsibility
connect / init_dbCreate the state directory, open SQLite, create tables, and apply small compatibility migrations.
clean_linesExtract text from DOCX XML or PDF through pdftotext.
parse_timetableRecognize weekday, time range, activity title, and category rows.
import_documentsImport timetable blocks and contest events into the database.
agendaReturn today's relevant rows, class display names, current block, and next block.
display_titleMap course codes to friendly names such as Drones Lab and Embedded Class.
due_notificationsCalculate lead/start/missed reminders and write notification keys to prevent repeats.
CLI handlersImplement init, agenda, tasks, add, move, delete, block completion, reminders, and settings.

5. Task and date/time workflow

  1. Enter a task title in the Kanban input and press Enter or Add.
  2. When the text ends with @, the calendar opens after a short debounce.
  3. Choose a date with the mouse or arrow keys and press Enter.
  4. When the text ends with @@, the time picker opens.
  5. Choose hour and minute using arrows, mouse, or keyboard and select Use time.
  6. The backend normalizes date/time values before storing them.
  7. The card computes and displays a relative value such as Due in 14h or Due in 1d 9h.

Date-only tasks use the end of that date for relative calculations. Time-only tasks display the selected time. Tasks with neither value do not show a due indicator.

6. Timetable classes

7. Reminder behavior

Default settings are a 10-minute lead reminder and a reminder at block start. Missed-block reminders are disabled by default. Settings can be viewed or changed with:

python3 planner.py settings
python3 planner.py settings lead_minutes 15
python3 planner.py settings notify_at_start 0
python3 planner.py settings notify_missed 1

Reminder keys combine the date, block ID, and reminder type. This prevents the 30-second service loop from repeatedly notifying for the same event.

8. Validation and maintenance

qmllint BarWidget.qml PlannerPanel.qml PlannerService.qml
omarchy plugin validate .
python3 -m unittest discover -s tests -v
python3 planner.py init
python3 planner.py agenda
python3 planner.py tasks

After a source update, push to GitHub, run omarchy plugin update study-planner --yes, and restart with omarchy restart shell if the panel does not reload. If it still does not open, inspect the current Quickshell log for QML errors.

9. Development history and handoff

The project began as a schedule/reminder and Kanban plugin, was renamed to study-planner, and was published to the GitHub repository above. Drag/drop was later removed after unreliable behavior. The UI was then refined for column layout, date/time pickers, relative due labels, class-name mapping, Omarchy-compatible typography, compact sizing, and cursor feedback.

The accompanying SESSION_HANDOFF.md is the authoritative continuation note for this development session. The current repository commit when this document was created is 6f340ca.
